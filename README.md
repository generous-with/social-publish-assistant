# 社交发布助手 · Social Publish Assistant

Chrome / Edge Manifest V3 扩展。从本地多平台标题 TXT 提取文案，在创作平台网页内预览并自动填写。无需构建、API Key 或后台服务，最终发布由用户操作。

## 安装

1. 下载 Releases 中的安装 ZIP，解压到固定目录；也可克隆本仓库。
2. 打开 chrome://extensions 或 edge://extensions，开启开发者模式。
3. 选择“加载已解压的扩展程序”，选取包含 manifest.json 的目录。
4. 登录创作平台，上传视频并进入编辑页，点击扩展图标。
5. 首次选择多平台标题 TXT（文件会在本机记住，切换平台后自动提取对应段落），检查文案后点击“填写当前页面”。已有不同内容需勾选替换。

更新后重新加载扩展，再点击图标重建面板；当前文案会保留。首次使用新平台前核对实际填写结果。

## 平台与功能

| 平台 | 页面 | 填写行为 |
| --- | --- | --- |
| 抖音 | creator.douyin.com/creator-micro/content/post/video | 标题、简介、逐个话题和回车、自主声明（无需添加自主声明） |
| 今日头条 | mp.toutiao.com/profile_v4/xigua/upload-video | 标题、简介、搜索候选后逐个话题回车、作品声明（自行拍摄）、关注引导贴纸（智能添加） |
| B站 | member.bilibili.com/platform/upload/video/frame | 标题、简介、标签、人工智能分区、个人观点声明、更多设置中的粉丝动态 |
| 小红书视频 | creator.xiaohongshu.com/publish/publish 的「上传视频」页（支持无 `target` 参数的入口） | 标题、正文、逐个选择话题下拉首项、原创声明协议及确认 |
| 小红书长文 | creator.xiaohongshu.com/publish/publish?target=article | 长文、一键排版、两张配图、4:3 首图排序、发布描述、话题和原创声明 |
| 知乎视频 | www.zhihu.com/upload-video | 标题、简介/正文，#后输入名称选择第一候选；个人观点标记、科技互联网领域 |
| 知乎文章 | zhuanlan.zhihu.com/write 或草稿编辑页 | Markdown 标题和正文、三张正文配图、独立 16:9 封面 |
| YouTube | studio.youtube.com/channel/.../videos/upload | 标题、说明、非儿童受众、展开后整体填入逗号标签 |
| Facebook | www.facebook.com/post/create | 使用抖音简介原文（含 #话题）、选择接收消息、打开 AI 标签 |
| X | x.com/home、x.com/compose/post | 使用抖音简介原文，含#话题，填写首页或新帖窗口 |

B站可自动清理表单已选标签，助手文案保持原样；超过10个时按顺序最多填写10个，并列出未填入项。小红书自动原创声明可在面板取消勾选。扩展不会点击发布、投稿、Post 或 YouTube“继续”，也不会修改公开范围。

## 今日头条文章

在头条号的文章编辑页打开扩展，选择 UTF-8 Markdown 文件。助手用第一个一级标题作为文章标题，预览其余正文，省略“作者：大书大 | 原创技术干货”署名和“写在最后”起的尾节。可以选三张 16:9 的 JPEG 或 PNG，按文件列表顺序插入正文。超过 5 MB 的图片会在浏览器本地压缩为 JPEG 后用于填写，原文件保留。文章以引用开头时，第一张图放在整段开头引用之后。其余图片优先使用 Markdown 图片占位，否则分散到正文各段之间。

同一编辑标签页关闭再打开助手时，保留已选文件和预览。确认预览后点击“填写文章”。勾选替换时，助手先确认旧正文和配图已清空。助手会填写标题和正文，通过头条编辑器图片工具栏的“本地上传”逐张插入配图，并清理图片相邻的空段落并勾选“个人观点，仅供参考”，最后显示填写结果。请核对后手动发布。Markdown 预览使用随包附带的 [markdown-it](markdown-it-LICENSE.txt)。

## 小红书长文

在发布页切到「写长文」后打开扩展。长文可粘贴或导入 Markdown/TXT。Markdown 开头的一级标题会带入标题栏。发布描述和话题取自多平台标题 TXT 的【小红书】段落，可复用上次选择的 TXT。

选择一张排版配图和一张 4:3 首图，点击「填写长文并排版」。助手在排版预览上传配图，生成后核对配图是否出现在排版成品里，再在「图片编辑」把 4:3 首图排第 1 张、带配图的排版成品排第 2 张。若模板没有配图入口，或生成的成品缺少配图，助手会尝试「理性现代」。助手在发布描述末尾逐个输入话题并选择下拉第一项，再按面板选项开启原创声明。

## 知乎文章

在知乎专栏写文章页面打开助手，导入带一级标题的 Markdown 文件，选择一张 16:9 JPEG 或 PNG 封面。正文配图可选，选择时请一次选三张。预览会显示每张图的插入位置，填写时通过知乎编辑器的上传控件插入并核对位置，封面通过独立控件上传。助手会选择创作声明「包含剧透」并开启送礼物。已有草稿可以点「仅应用发布设置」。知乎首次确认开启送礼物时即接受平台的《知乎赞赏功能使用协议》。填写完成后，请核对草稿再手动发布。

## TXT 格式

见 [完整示例](examples/multi-platform.txt)。段落使用【平台名】，字段使用中文冒号。支持UTF-8/BOM及GB18030。B站支持【B站】和【B 站】；知乎支持“简介”或“正文”；YouTube支持繁体字段名。Facebook与X复用【抖音】简介，不需要单独段落。

B站标签按空格拆分，因此 AI Agent 会计为两项；YouTube按逗号拆分，AI Agent 保留一项。不要选择口播全文文件。浏览器不能按任意磁盘路径静默读取文件，必须通过文件选择器授权。

## 隐私与权限

仅申请 activeTab、scripting、storage。点击工具栏后注入当前页面，不申请全站后台访问，不使用远程代码、统计或外部AI服务。草稿保存在扩展本机 storage.local，填写内容会交给目标网站，网站可能自动保存草稿。详见 [隐私说明](PRIVACY.md)。

## 局限和反馈

平台DOM、富文本编辑器和合成事件处理随时可能变化。已有自动化验证含真实文件解析与模拟浏览器，不等同于所有平台的当前线上验收；非Chrome浏览器需自行核验。遇到失败，点击“复制诊断”，检查并脱敏后提交Issue，注明平台、浏览器、扩展版本及操作步骤。诊断可能包含候选话题、页面标签和身份相关属性，不要直接公开含隐私的完整页面。

本地预检与平台实际字数规则可能不同，尤其X中文权重、YouTube标签计数和会员功能限制。导入时标题、简介和B站粉丝动态超过本地上限会自动截取，并显示原长度及截取后长度；小红书正文预留话题空间。请检查截取后的语义完整性，发布前以平台计数和提示为准。

## 开发与验证

Node.js 18+，不需要安装依赖：

~~~sh
npm test
npm run check
npm run package
~~~

安装包输出到 dist/。解析器位于 parser.js，面板与消息分派为 panel.js/background.js，各平台适配在 *-fill.js。运行时无构建步骤。测试不使用个人素材或登录账号，不会真实发帖。
